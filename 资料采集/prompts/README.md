# 采集任务书

每个文件是一份自足的任务书，可以整份交给一个能联网的模型或代理去做。共 16 份，对应 12 项资料。

## 怎么用

1. 执行者要能读写这个仓库：读 `申论/`、`analysis/out/`、`素材库/`，写 `资料采集/`。
2. 一份任务书开一个会话，整份贴进去。`01` 的五份互不依赖，可以同时跑。
3. 交回来以后先跑 `python3 资料采集/check_collect.py 资料采集/<目录>`，看格式和 A 级引文；再按任务书末尾的"验收"抽查。
4. 执行者如果在原语料所在的机器上（`/home/fires/projects/Learn-to-Write/corpus/articles/cn/`），`03a`、`06`、`10` 三份可以先用本地原文，引文直接做到 A。

## 建议顺序

1. `01`（五份并行）、`03a`、`02`：其余几项要用它们的结果。
2. `04a`、`04b`、`05`、`06`、`10`。`04a` 会按 `01` 查出的真实原型去找官方概括。
3. `03b`、`07`、`08`、`09`。`09` 用 `03b` 的《求是》目录核对重刊日期。

## 逐字状态的两套口径

上一轮留下的文件用的是旧口径：A＝两处来源一致，B＝单一来源抽取，C＝转述，都没有存原文。任务书里改成了新口径：A＝原文已存进 `raw/`、能逐字找到，B＝两处来源一致，C＝单一来源或转述。所以旧文件里的 A 按新口径只算 B，`check_collect.py` 会把它们报成"标了 A，但 raw/ 里没有原文"，这是预期的，续做时逐条补原文或改标。

## 为什么改成任务书

聊天会话里的子任务共用一份检索额度（每轮 200 次检索，抓取每小时 800 次），15 路同时跑，五分钟左右就用完；会话的命令行也连不上政府网站和官媒。任务量本身需要的检索在千次以上，适合交给没有这个上限、能直接抓网页的执行者。
