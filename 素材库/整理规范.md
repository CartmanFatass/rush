# 素材库整理规范

写给做整理的人。先读完这份，再读任务说明里指给你的文件。

## 这个素材库是干什么的

给一位备考 2027 年度国考（国家金融监督管理总局，计算机类岗位）的考生用，只服务三件事：

1. 行测的时政题（单选、多选）。
2. 申论大作文：追踪重点题材，以及对应的素材和常见观点的论证。
3. 申论的规范表述（概括、分析、对策题用的规范说法）由现有申论手册覆盖，会议素材中不重复另建。

本规范约束复习素材汇编的精炼表达。正式教学按根目录 `学习计划.md` 连贯讲清概念、过程与边界；不以短卡片替代完整讲解。原文用于查证，研究报告用于核对方法和统计。个人状态只记录在根目录 `进度.md`。

## 三个成果

| 成果 | 路径 | 内容 |
|---|---|---|
| 一、会议考点总表 | `素材库/1-会议考点总表/` | 一场会议（或一份文件）一条。六栏：名称、日期、文件、核心部署、重要新提法、可能混淆的表述。服务时政题 |

| 三、速记与模拟题 | `素材库/3-速记与模拟题/` | 易混术语对照、会议和文件的对应、数字型考点、重大部署的关键词；自编单选、多选题 |

## 写法

1. **原文短语一律写成「……」**。凡是从文件里取的提法、术语、数字，都用直角引号「」括起来，要逐字。后面可以跟来源代号，如「管得好」〔经济会〕；不跟代号时，必须能在本文件来源表列出的某份文件里找到。整句引用可以单独成行，以 `>` 开头、〔代号〕结尾。自己的概括和连接语不加「」。
2. **每个文件末尾有"## 来源"表**：代号、文件、发布日期、本地路径。路径写在最后一列的反引号里，相对语料根 `/home/fires/projects/Learn-to-Write/corpus/articles/cn/`。
3. **写完必须校验**：在 `/home/fires/projects/rush` 下运行 `python3 analysis/check_quotes.py 你的文件`，必须 0 处问题。校验不过的短语，改成原文的写法或去掉「」并改成自己的概括，不许为了通过而把原文短语的「」去掉后仍当原文用。
4. **同一个提法在几份文件里写法不同的，并排列出**，注明各出自哪份。这是"可能混淆的表述"和"易混术语"的主要来源。新旧提法对照（如上年和今年）同样处理。
5. **考点分三类**，在适当处标明：必须准确记忆的事实（名称、日期、数字、原词）；需要理解的政策逻辑；可以用于申论的素材。
6. **不按会议写长总结**。成果一每条是一张六栏的表加必要的两三句说明；跨会议的关联放进"可能混淆的表述"一栏。
7. **篇幅**：三个成果合计 20–30 页（一页按 800 字算）。各任务说明里有具体字数上限，宁短勿长。原文摘录里已有的内容，挑要紧的用，不要全搬。

## 不要写的东西

- 不写"出题可能"、提前量、命题规律之类的分析。
- 不写学习日程、时间分配、提分估计，不对考生水平作假设。
- 不写"必考""押题""大概率考"。
- 不写"怎么用这份材料"之类的说明段，不写鼓励的话。
- 不引培训机构讲义的说法当依据。
- 模拟题要标明"自编"，并在每题后给出答案和原文出处。

## 边界

只新建或修改任务说明里指定的文件。不改 `素材库/原文摘录/`、`analysis/`、`申论手册/` 和其他任何文件，不做 git 提交，不启动别的代理。文风平实，像给同事写的参考资料；并列的事实用表格，解释用整句。
